# API авторизации

Java 26, Spring Boot 4.1.1, Spring Security, Spring Data JPA/Hibernate, Flyway, PostgreSQL. Исходники восстановлены из локальной копии предыдущей разработки. В ветке `origin/codex/local-auth-backend` остались только `backend/target` и отчёты тестов; эти скомпилированные файлы не включены в исходники. `target/` и локальный JDK исключены из Git.

Все ответы: `{ "ok": true, "data": ... }` либо `{ "ok": false, "error": "..." }`. При ограничении частоты сервис может вернуть `retryAfterSeconds` и `Retry-After`.

| Метод | Адрес | Данные/назначение |
| --- | --- | --- |
| GET | `/api/auth/csrf` | Получить `token` и `headerName`; использовать перед POST с той же cookie |
| POST | `/api/auth/identify` | `email`; следующий шаг формы |
| POST | `/api/auth/register` | `email`, `password`, `consentAccepted: true`; отправить код |
| POST | `/api/auth/verify-email` | `email`, `code`; подтвердить и войти |
| POST | `/api/auth/resend-code` | `email`; новый код |
| POST | `/api/auth/sign-in` | `email`, `password`; войти |
| POST | `/api/auth/sign-out` | `{}`; выйти |
| GET | `/api/auth/me` | Текущий пользователь; без сессии 401 |
| POST | `/api/auth/request-password-reset` | `email`; отправить ссылку |
| POST | `/api/auth/reset-password` | `token`, `password`; сменить пароль |

Пароль: минимум 8 символов, максимум 72 байта UTF-8 (ограничение BCrypt). Код регистрации привязан к сессии браузера, который запросил регистрацию. При потере этой сессии регистрацию нужно начать заново. Лимит пароля также проверяется сервером для многобайтовых символов.

Flyway создаёт `app_users` и `email_verifications`. Неподтверждённая регистрация не создаёт активного пользователя. Сбой SMTP откатывает выдачу кода; ошибки проверок кода сохраняют счётчик попыток. Повторное использование кода или reset token отклоняется.

Ссылка восстановления содержит токен в URL fragment (`#token=...`), чтобы он не попадал в серверный access log и Referer; в БД хранится его SHA-256.

## Границы текущей реализации

- Сессии хранятся в памяти одного Java-процесса и теряются при перезапуске. Для нескольких экземпляров нужен общий session store.
- Ограничение частоты хранится в памяти и использует адрес непосредственного клиента. За Next.js/другим proxy это адрес proxy; перед публичным запуском следует настроить лимиты на доверенном внешнем proxy. Произвольному клиентскому `X-Forwarded-For` сервер не доверяет.
- Для публичного запуска нужны HTTPS, `COOKIE_SECURE=true`, реальный SMTP, отдельные пароль БД и адрес `FRONTEND_URL`. Текущие значения предназначены для локального Compose.
- `/identify` нужен для согласованного email-first интерфейса и раскрывает существование аккаунта; смена пароля этого не раскрывает.
- Backend и фронтенд должны быть доступны браузеру через один origin (`/api/*` проксируется). Локальный Next.js proxy уже включён. При статическом размещении на REG.RU это должен делать веб-сервер.

## Автоматические проверки

`AuthIntegrationTest` проверяет регистрацию и подтверждение, привязку к сессии, повторное использование и срок кодов, попытки/повторную отправку, вход и блокировку, выход, восстановление и истечение ссылки, завершение сессий после смены пароля, валидацию, CSRF и откат при отказе SMTP.

Тесты работают в схеме `auth_test`; `TEST_DATABASE_URL` позволяет использовать PostgreSQL из GitLab CI. Не направляйте тесты в production-базу. HTTP-проверка `scripts/auth-smoke.py` отдельно проверяет Next.js proxy, cookie и письма Mailpit.
