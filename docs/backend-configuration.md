# Настройки backend и document-worker

Настройки выполнения отделены от фиксированного контракта данных.
Поведение без overrides сохранено. Для изменения настроек нужен перезапуск процесса.

## Где менять

Для API задавайте ENV из таблиц ниже или добавляйте `KEY=value` в `backend/.env.local`.
Значения по умолчанию видны в `backend/src/main/resources/application.yaml`.
Также доступны стандартные Spring properties, например
`--godeck.ai-edit.max-edits-per-window=50`. Не добавляйте секреты в YAML или Git.

Существующий `GODECK_OPENAI_RESPONSES_URL` теперь одинаково применяется к генерации и
правкам блока. По умолчанию используется прежний OpenAI endpoint; override предназначен
для доверенного совместимого сервиса или локальной тестовой фикстуры.

Spring связывает параметры с небольшими immutable records по назначению:

- `GenerationSettings` — приём генераций, квоты публикаций/старого чата и сроки резервирования;
- `AiEditSettings` — квота предложений для блока, сетевые таймауты и очистка AI-журнала;
- `MaterialJobSettings` — очередь исходных документов и срок доступности результата.
- `AuthSettings` — сроки кода/reset, cooldown, блокировка входа и защита по IP;
- `ImageSettings` — размеры и квоты приватных изображений;
- `TextEditPromptSettings` — стоимость/контекст предложений AI, отдельно от сетевых таймаутов.

Значения `@DefaultValue` позволяют использовать те же безопасные defaults без YAML, например
в изолированном контексте теста. YAML содержит эквивалентные defaults и удобные ENV-имена.
Не добавляем тестовые конструкторы или изменяемые глобальные настройки в production-код.

## Генерация и публикации

| ENV | Default | Назначение |
| --- | --- | --- |
| `GENERATION_MAX_PER_WINDOW` | `10` | Созданий презентации на пользователя за окно |
| `GENERATION_MAX_ACTIVE` | `3` | Незавершённых презентаций пользователя одновременно |
| `PRESENTATION_MAX_EDITS_PER_WINDOW` | `30` | Повторных публикаций/правок старого чата за окно |
| `GENERATION_QUOTA_WINDOW` | `24h` | Скользящее, не календарное окно квоты |
| `GENERATION_CONNECT_TIMEOUT` | `10s` | Установка соединения с AI |
| `GENERATION_READ_TIMEOUT` | `2m` | Ожидание HTTP-ответа AI |
| `GENERATION_JOB_TIMEOUT` | `5m` | Когда running-задача считается прерванной |
| `PRESENTATION_EDIT_LEASE_TIMEOUT` | `5m` | Когда разрешено заменить зависшее резервирование публикации |
| `GENERATION_POLL_MS` | `1500` | Интервал проверки очереди генераций, миллисекунды |
| `GENERATION_SOURCE_RETENTION` | `30d` | Хранение копии исходника после первого terminal-состояния |
| `GENERATION_MAX_OUTPUT_TOKENS` | `12000` | Бюджет ответа при генерации презентации |

Первая публикация v0 → v1 по-прежнему не расходует квоту повторных публикаций.
Autosave `/draft` не создаёт PPTX и не расходует эту квоту. `/commit` сохраняет проверки
точной base version, draft revision и lease. Таймаут lease не является жёстким watchdog рендера.

## PDF

Настройки визуального PDF: `PDF_EXPORT_DPI=144` (72–216) и `PDF_EXPORT_MAX_CONCURRENT=2` (1–4).
Они связываются с `PdfExportSettings`; ограничения и расход памяти описаны в [экспорте](presentation-export.md).

## AI-правки отдельного блока

| ENV | Default | Назначение |
| --- | --- | --- |
| `AI_EDIT_MAX_PER_WINDOW` | `100` | Предложений на пользователя за окно |
| `AI_EDIT_QUOTA_WINDOW` | `24h` | Скользящее окно отдельной квоты AI-чата |
| `AI_EDIT_CONNECT_TIMEOUT` | `10s` | Установка соединения |
| `AI_EDIT_READ_TIMEOUT` | `30s` | Ожидание ответа |
| `AI_EDIT_STALE_AFTER` | `2m` | Когда незавершённая правка считается зависшей |
| `AI_EDIT_RETENTION` | `90d` | Хранение AI-правок и TEXT_EDIT provider exchanges |
| `AI_EDIT_RETENTION_BATCH_SIZE` | `1000` | Размер короткой транзакции удаления |
| `AI_EDIT_RETENTION_CRON` | `0 17 3 * * *` | Расписание очистки, UTC |

Каталог, ответ с оставшейся квотой и сообщение 429 не зашивают старый дневной лимит.
Успешный повтор с тем же request id не тратит квоту второй раз. Очистка не удаляет
историю генераций и старого чата. Реальные запросы/ответы AI по-прежнему доступны владельцу;
в обычные серверные логи тела документов и ключи не выводятся.

## Исходные документы

| ENV | Default | Назначение |
| --- | --- | --- |
| `MATERIAL_JOBS_MAX_ACTIVE` | `20` | queued/running jobs глобально |
| `MATERIAL_JOBS_MAX_ACTIVE_PER_USER` | `2` | queued/running jobs одного пользователя |
| `MATERIAL_JOBS_QUEUE_TIMEOUT` | `60s` | Сколько queued job может ждать worker |
| `MATERIAL_JOBS_RESULT_TTL` | `1h` | От создания job до удаления результата |
| `MATERIAL_JOBS_CLEANUP_INTERVAL` | `60s` | Проверка просроченных jobs |
| `MATERIAL_INPUT_CLEANUP_MS` | `3600000` | Проверка истёкших копий исходников в презентациях |

API явно записывает deadline и expires_at в БД. Увеличение ENV действительно меняет срок,
а не оставляет старый DB DEFAULT. Смена настроек не переписывает сроки уже созданных jobs.
Worker получает отдельный claim deadline после начала обработки. Доступ к результату
по-прежнему ограничен владельцем; payload удаляется при любом терминальном исходе.

Для отдельного worker используйте ENV из [его README](../document-worker/README.md).
Локальный `pnpm document-worker:dev` наследует ENV терминала; `backend/.env.local` сам по себе
не загружается plain Java worker. Compose явно пробрасывает шесть worker-параметров.
Не переиспользуйте API timeout как worker watchdog: это разные процессы и виды работы.

## Проверка при запуске

Квоты, batch sizes и длительности должны быть положительными. Job/lease/stale deadlines
должны превышать сумму connect + read timeout соответствующего HTTP-клиента. Result TTL
должен превышать время ожидания в очереди. Некорректная конфигурация останавливает API до
приёма запросов. Это минимальный запас, не гарантия максимального времени полного рендера.

## Авторизация и письма

| ENV | Default | Назначение |
| --- | --- | --- |
| `AUTH_CODE_TTL` | `10m` | Срок email-кода; целые минуты |
| `AUTH_RESET_TTL` | `30m` | Срок reset-токена; целые минуты |
| `AUTH_LOGIN_LOCK` | `15m` | Блокировка после неверных паролей |
| `AUTH_RESEND_COOLDOWN` | `60s` | Повтор письма; целые секунды, те же в HTTP-ответе |
| `AUTH_MAX_FAILED_ATTEMPTS` | `5` | Неверных кодов/паролей до блокировки |
| `AUTH_MAX_TRACKED_IP_ADDRESSES` | `10000` | Максимум отслеживаемых адресов одного процесса |
| `AUTH_MAX_REQUESTS_PER_WINDOW` | `100` | Auth-запросов с адреса за окно |
| `AUTH_REQUEST_WINDOW` | `15m` | Окно защиты запросов |
| `SESSION_TIMEOUT` | `7d` | Таймаут HTTP-сессии |
| `SMTP_CONNECT_TIMEOUT_MS` | `5000` | Подключение к SMTP |
| `SMTP_READ_TIMEOUT_MS` | `5000` | Чтение SMTP |
| `SMTP_WRITE_TIMEOUT_MS` | `5000` | Запись SMTP |

В письме отображается реальный настроенный TTL. Code/reset требуют целых минут, чтобы текст
письма не округлял срок; остальные длительности и счётчики валидируются при старте.
Формат кода, reset-токена, предел bcrypt и server-side session/CSRF не изменяются.
IP-защита остаётся локальной для процесса, не новым распределённым rate limiter.

## Изображения

| ENV | Default | Назначение |
| --- | --- | --- |
| `IMAGE_MAX_UPLOAD_SIZE` | `10MB` | Исходное и нормализованное PNG; можно только ужесточить |
| `IMAGE_MAX_DIMENSION` | `8192` | Длина стороны, не выше безопасного ceiling |
| `IMAGE_MAX_PIXELS` | `32000000` | Число пикселей, не выше безопасного ceiling |
| `IMAGE_MAX_PER_PRESENTATION` | `100` | Число сохранённых assets |
| `IMAGE_MAX_STORAGE_SIZE` | `100MB` | Сумма нормализованных приватных PNG |

Здесь MB — двоичные единицы Spring DataSize, например 10 × 1024 × 1024 байт.
Frontend/multipart по-прежнему ограничивают загрузку 10 MiB. Серверный override может отказать
раньше, но не разрешает обойти этот контракт. Реальные пути, namespace презентации и повторное
кодирование PNG сохранены.

## Бюджеты AI-правки

| ENV | Default | Назначение |
| --- | --- | --- |
| `AI_EDIT_MAX_OUTPUT_TOKENS` | `2048` | Потолок ответа |
| `AI_EDIT_BASE_OUTPUT_TOKENS` | `256` | База формулы base + variants × ceil(max_chars / 2) |
| `AI_EDIT_SHORTEN_RATIO` | `0.7` | Целевая доля длины; строго между 0 и 1 |
| `AI_EDIT_TITLE_MAX_CHARS` | `80` | Длина каждого заголовка в контексте |
| `AI_EDIT_ROLE_MAX_CHARS` | `160` | Длина описания роли поля |
| `AI_EDIT_GPT54_MINI_REASONING_EFFORT` | `low` | Reasoning для gpt-5.4-mini |
| `AI_EDIT_GPT54_REASONING_EFFORT` | `low` | Reasoning для gpt-5.4 |

Ключи моделей в YAML заключены в квадратные скобки, чтобы Spring сохранил точки в именах.
Для совместимой модели можно добавить `godeck.ai-edit.prompt.reasoning-efforts.[model-id]`;
пустое значение убирает reasoning для указанной модели. Не задавайте неподдерживаемые провайдером
значения. Модель вне карты не получает reasoning. Полный AI-ответ не обрезается этими настройками:
превышение поля остаётся предупреждением, превышение hard-limit запрещает применение.

## Что сознательно осталось константами и что дальше

Не превращаем в независимые ENV ограничения, которые уже являются контрактом UI/API/БД:
5 МиБ исходника, 30 000 символов, 20 PDF-страниц, DTO/колонки, поддерживаемые форматы,
идентификаторы SQL locks. Для изменения таких максимумов нужна согласованная правка всех слоёв.

Остальные константы описывают формат/контракт или алгоритмы: предопределённые шаблоны и каталог
поддерживаемых моделей, геометрия и стиль, длины DTO/колонок, технические идентификаторы и правила
нормализации. Они не превращены в произвольные ENV. Их изменение требует продуктового решения
и проверки совместимости, а не настройки конкретного сервера.
