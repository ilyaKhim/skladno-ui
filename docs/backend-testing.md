# Тесты backend

## Как запускать

Из корня репозитория:

```sh
pnpm backend:test:unit         # без Spring-контекста, PostgreSQL и внешней сети
pnpm infra:up                 # PostgreSQL и Mailpit для локальной работы
pnpm backend:test:integration  # Spring + настоящая PostgreSQL, отдельные тестовые схемы
pnpm backend:test             # весь набор
pnpm document-worker:test     # парсеры в отдельном Java-модуле
```

Скрипт выбирает локальный JDK 26 из `.tools`, если он установлен. Maven-зависимости должны быть доступны локально или загружены при первом запуске. Для CI/PostgreSQL можно задать `TEST_DATABASE_URL`, `DATABASE_USER` и `DATABASE_PASSWORD`. Интеграционные тесты используют схемы `auth_test` и `generation_test`; рабочая схема `public` не очищается. Выполняйте их на локальной или выделенной тестовой БД. Тестовые AI-клиенты не отправляют запросы в OpenAI.

Очередь материалов проверяется отдельно в схеме `material_test`: владелец, CSRF, ограничения загрузки и очереди, просроченные claims и удаление исходных байтов. Парсеры находятся в `document-worker/src/test`, а настоящий упакованный worker запускается вместе с API в браузерных E2E. `pnpm test:migrations` проверяет переход старых неопубликованных результатов в черновики в одноразовой схеме. GitLab запускает проверки обоих Java-модулей; миграцию и связку с worker проверяет job `editor_e2e`.

Для сборки с нуля из `backend/`, при настроенном Java 26:

```sh
./mvnw --batch-mode clean verify
```

## Unit-тесты

| Область | Что проверяется |
| --- | --- |
| Авторизация | Нормализация email, retry только конкретного конфликта регистрации, отсутствие retry при SMTP/других ошибках БД, длина пароля в UTF-8 байтах, dummy comparison неизвестного аккаунта, точные сроки блокировки и кода |
| Письма и сообщения | Подстановка кода/сроков, ссылка с fragment, нормализация URL, наличие текста для каждого публичного кода ошибки |
| Security filter | Окно ограничения запросов, независимость IP, игнорирование поддельного X-Forwarded-For, отзыв сессии, debug identity без обращения к БД, запрет debug bypass на внешнем адресе |
| Контент и PPTX | Строгий JSON, поля шаблона и маркеры, недопустимые решения по слайдам, неизменяемый нормализованный план, безопасное сокращение Unicode, подстановка полей в настоящий PPTX |
| Файлы | Уникальная атомарная запись, удаление временного файла при ошибке рендера, сохранность предыдущего файла, защита от выхода за каталог/символических ссылок, некорректные пути, повторная очистка |
| Пагинация | Произвольный offset, навигация, порядок, неверные параметры и переполнение |
| AI HTTP-клиент | JSON Schema и заголовки настоящего HTTP-запроса, завершённый/незавершённый/пустой ответ, некорректный план, HTTP-ошибка провайдера, отсутствие запросов без ключа или при выключенном AI, offline preview |

`MockRestServiceServer` перехватывает запросы `RestClient` внутри процесса: это проверка формирования/чтения HTTP, а не обращение к реальному провайдеру. Конструктор генератора принимает готовый HTTP-клиент, а таймауты production-клиента задаёт `OpenAiClientConfig`.

## Интеграционные тесты

Здесь поднимаются Spring MVC, Spring Security, сервисы, JPA и Flyway. SQL fixtures/assertions читают реальное состояние PostgreSQL независимо от JPA.

- Регистрация и вход: хеши, challenge, cooldown, неверные коды и пароли, SMTP rollback при создании/замене/повторной отправке, восстановление пароля, cookies/session rotation.
- Конкурентность: один аккаунт при двух подтверждениях, одно использование reset-токена, отсутствие потерянных счётчиков входа, два первых запроса регистрации, идемпотентное создание проекта и блокировки правок. Конкурентные задачи синхронизируются latch и имеют ограниченное ожидание; `Thread.sleep` для гонок не используется.
- Доступ: анонимный запрос не читает/не создаёт проекты, чужой пользователь не читает/не изменяет презентацию, списки разделены по аккаунтам, CSRF обязателен, отозванная сессия теряет доступ к API.
- Очередь: отменённая задача не запускается, занятая строка пропускается, сбой AI или устаревшая модель не задерживают следующую задачу, прерванная задача не может завершиться после восстановления. Ручной рендер не зависит от доступности AI-модели.
- Правки: AI вызывается без транзакции БД, параллельная правка отклоняется, устаревший токен не затирает новый результат. Реальный конфликт уникальности версии откатывает новый указатель/версию, освобождает lease и удаляет новый файл, сохраняя прежний PPTX.
- API: DTO, некорректные UUID/числовые параметры, 409 при занятой записи, ручная сборка/скачивание, версии, выбор модели и окно пагинации.

Состояние схем очищается перед каждым тестом; временные PPTX тестов удаляются после набора. Внешний SMTP заменён тестовым outbox.

## HTTP smoke и границы проверок

Дополнительно проверяйте связку frontend → Next.js proxy → backend → PostgreSQL/Mailpit:

```sh
AUTH_BYPASS=false FRONTEND_URL=http://localhost:3001 pnpm backend:dev
# В другом терминале, с frontend на 3001:
AUTH_BASE_URL=http://localhost:3001 pnpm test:auth
```

Smoke создаёт один локальный аккаунт и два письма Mailpit; проверяет регистрацию, код, вход/выход, смену пароля и отзыв сессии. Это отдельная проверка работающих процессов, не часть Maven unit/integration набора.

Число в отчёте Surefire включает каждую строку параметризованного теста. Набор не подтверждает доступность реального OpenAI, качество сгенерированного текста или состояние production. Сбой процесса между записью файла и commit может оставить файл без ссылки — файловая система и PostgreSQL не являются одной распределённой транзакцией. Квоты генерации сейчас являются ограничениями по подсчёту записей; строгая глобальная квота при параллельных запросах с разными ключами не обеспечивается отдельной атомарной операцией.

## AI-правка текста и длинный текст в редакторе

Модель заменена `ScriptedTextEditLlm` (`godeck.ai-edit.llm=scripted`, профиль `test`); OpenAI не
вызывается. Интеграционные тесты используют схемы `ai_edit_test` и `editor_text_test`.

- Unit: `TextEditActionRegistryTest` (уникальность id, ровно одно `input`-действие, каталог совпадает
  с примером контракта, строгая валидация параметров), `TextEditRequestFactoryTest` (снимок `input`
  для каждого действия, только минимальный контекст, strict schema, `store: false`, формула
  `max_output_tokens`), `TextEditResponseParserTest`, `TextResultSanitizerTest` (кавычки, markdown,
  переносы, маркеры, предупреждения; текст не обрезается), `TargetResolverTest` (заголовки, aurora без
  sidecar, исключённый слайд, чужое поле, блок только в черновике/опубликованном документе, лимиты),
  `ScriptedTextEditLlmTest` (заглушка не стартует вне `test`/`e2e`),
  `PresentationContentValidatorOverflowTest` (граница `hard` для 7/46/170/3000, `TRUNCATE` прежний).
- Golden: `PresentationRequestGoldenTest` сравнивает тело запроса генерации со снимком
  `src/test/resources/golden/presentation-generation-request.json` (окончания строк нормализуются).
  Намеренное изменение — `./mvnw test -Dtest=PresentationRequestGoldenTest -Dgodeck.golden.update=true`.
- `AiTextEditIntegrationTest`: каталог и `enabled: false`, 200 для поля и блока с записью в обоих
  журналах, неизменность документа и файлов, уточнение и `refines_edit_id`, `__LONG__`/`__HUGE__`
  без обрезки и с одним вызовом, `unsupported`, 401/403/404/409, каждый код 422 без вызова модели,
  квота (101-й запрос → 429 с временем сброса), идемпотентность и параллельный дубль (один вызов),
  autosave и экспорт во время вызова, отсутствие транзакции во время вызова, зависшая `running`,
  ошибка провайдера, хранение 90 дней.
- `EditorLongTextIntegrationTest`: draft/`GET /editor`/commit сохраняют текст до `hard_max_chars`
  целиком (в `content_json` и PPTX), `hard + 1` → 422; генерация и ручная сборка по-прежнему обрезают.

На Windows без права создавать символические ссылки `PresentationFilesTest.outsidePathsAndSymlinksCannotBeDownloaded`
падает с `AccessDeniedException` до проверки — это ограничение окружения, а не кода.

## Проверки после ревью поддерживаемости

- `PresentationRequestFactoryTest`: строгая JSON Schema соответствует полям и номерам макетов выбранного шаблона.
- `PresentationContentGeneratorTest`: составной ответ модели собирается целиком; отказ записи диагностики не уничтожает ответ и не заменяет исходную ошибку; отказ записи запроса предотвращает неотслеживаемый вызов.
- `PresentationContentValidatorTest`: проверка плана без PPTX/I/O, сохранение явно включённых пустых макетов и корректная работа с Unicode при лимитах в 1–3 UTF-16 единицы.
- `PresentationTemplateServiceTest`: общий кешированный манифест и вложенные списки полей неизменяемы.

Написанный для студии API-клиент проверяется отдельно командой `pnpm test:frontend`; она также запускает существующие тесты разбора вставленного ответа LLM. Команда включена в `frontend_check` GitLab CI. Тесты проверяют сессию/CSRF, публичные ошибки, отмену запроса, ключ идемпотентности и неизменность отправляемого плана; OpenAI не вызывается.
