# Один редактор до и после первой публикации

AI-генерация и вставка ответа LLM подготавливают содержимое со статусом `draft` и версией `0`. На этом этапе PPTX и записей в истории версий нет. «Недавние» показывает «Черновик» и ссылку «Открыть редактор».

В обычном редакторе можно проверить текст, порядок и видимость слайдов, добавить изображения. Autosave (`PUT /editor/draft`) сохраняет JSON, не создавая PPTX. Доступны те слайды, которые включены в подготовленное содержимое. Скрытый слайд остаётся в файле PowerPoint, но не показывается при демонстрации; это не исключение из состава.

«Экспорт» → «Создать первую версию» дожидается сохранения и вызывает `POST /editor/commit` с точными `base_version: 0` и `draft_revision`. Этот же механизм позже создаёт версии 2, 3 и далее. Публикация не вызывает AI. Отдельных outline API и формы проверки структуры больше нет.

Конфликт вкладок сохраняет локальные правки, не перезаписывая сервер. Lease и ревизия защищают рендер от одновременного сохранения/отмены и запоздалого завершения. Повтор уже опубликованной пары base/revision возвращает существующую публикацию. При неизвестном результате экспорта редактор сначала повторяет/сверяет эту публикацию, не сохраняет поверх неё новые правки.

## Обновление существующей установки

Контрольная точка старой реализации: `ba47ce3`, ветка `feat/source-materials`. Рефакторинг находится в `refactor/document-worker-and-drafts`.

V12 добавляет очередь материалов. V13 переводит готовые неопубликованные результаты старой проверки/очереди в `draft`, сохраняя содержимое, и удаляет outline-поля. Существующие опубликованные версии и их файлы не меняются. Старые миграции не редактируются.

**Нельзя применять V13, оставив работающий старый API:** он обращается к удалённым колонкам. Порядок обновления: резервная копия → остановка старого API/генерации → запуск нового API с Flyway → запуск document-worker → обновление frontend. Пользовательские процессы и рабочая схема автоматически во время разработки не обновлялись.

`pnpm test:migrations` проверяет настоящую V13 на старых awaiting/queued/running снимках и опубликованной v4 в новой временной схеме. `e2e/drafts.spec.ts` проверяет отсутствие файла до публикации, сохранение/возвращение, порядок/hidden в настоящем PPTX, потерянный ответ, конкурентную публикацию и отмену.
