# Нумерация и экспорт

В редакторе «Экспорт» предлагает редактируемый PowerPoint и визуальный PDF для просмотра и печати.
Оба формата сначала сохраняют черновик и публикуют версию существующим `/editor/commit`, без вызова AI.
Затем скачивается именно эта версия, а не изменяемая ссылка на последний файл.

## Номера слайдов

В поставляемых шаблонах номер был обычным текстом `09`, `13` и т.д. в shape с именем `Folio`.
Теперь этот элемент заполняется текущим порядковым номером слайда, начиная с 1, с сохранением
позиции, цвета, гарнитуры и ведущего нуля. Остальные числа на слайде не меняются.
Обложки и шаблоны без `Folio` остаются без номера; обложка всё равно занимает позицию 1.

В браузере номер — отдельный, нередактируемый слой: перестановка сразу пересчитывает и основной
слайд, и миниатюры. Новый URL фона содержит `hide_number=true`, чтобы в PNG не оставался старый номер.
При публикации `TemplateRenderer` обновляет номер в PPTX. Уже опубликованные файлы истории
не переписываются: для исправленного PPTX нужно экспортировать новую версию.

## PDF для MVP

`PresentationPdfRenderer` читает опубликованный PPTX, рисует слайды через Apache POI и помещает
изображения в PDF через PDFBox. Размер страницы и порядок сохраняются. Текст в PDF нельзя выделять
или искать; анимации и интерактивность отсутствуют. PowerPoint/LibreOffice и отдельный сервис не нужны.
Соответствие редких эффектов и гарнитур ограничено возможностями POI и шрифтами сервера, как у PNG-фонов.

Скрытые слайды по умолчанию пропускаются. В меню можно включить их явно. Номера в PDF считаются
по фактически выгруженным страницам, без пропусков. В PPTX скрытые слайды остаются в составе.
Если все слайды скрыты, PDF без явного включения скрытых возвращает понятную ошибку.

Ошибка подготовки PDF не откатывает успешную публикацию. Повтор в том же редакторе использует
уже опубликованную версию без дополнительного commit. Если после ошибки пользователь изменил
документ, сначала сохраняется и публикуется новая версия. После перезагрузки страницы этот временный
контекст повтора не сохраняется; следующий экспорт работает как обычная новая публикация.

## API и настройки

Оба существующих GET поддерживают `format=pptx|pdf` (по умолчанию `pptx`):

- `/api/generation/v1/presentations/{id}/download`
- `/api/generation/v1/presentations/{id}/versions/{version}/download`

Для PDF есть `include_hidden=true|false` (по умолчанию `false`). Авторизация и проверка владельца
выполняются до чтения файла и конвертации. GET не изменяет историю. Ответ — private attachment с
`Cache-Control: no-store`; неизвестный формат — 422. Для публикации по-прежнему нужен CSRF.

- `PDF_EXPORT_DPI=144` — разрешение растра; допустимо 72–216. Больше DPI — больше памяти и файл.
- `PDF_EXPORT_MAX_CONCURRENT=2` — одновременно конвертируемых PDF на процесс; допустимо 1–4.
  При занятых слотах возвращается `429 / pdf_busy`, а не неограниченная очередь.

На Linux нужны `fontconfig`, системные шрифты и `java.desktop`, см. [деплой](deployment.md).
PDF создаётся по запросу в памяти, не сохраняется отдельно и не требует миграции БД.

## Проверки

`pnpm backend:test` проверяет реальные шаблоны, цвета/размер/порядок страниц PDF, скрытые слайды,
неизменность исходного PPTX, ошибки и изоляцию владельцев. `pnpm test:frontend` проверяет DTO и
скачивание. `pnpm test:e2e e2e/editor-export.spec.ts` проверяет номера после перестановки/reload,
реальные PPTX/PDF, скрытые слайды и повтор PDF без лишней публикации в Chromium и WebKit.
