# Генерация PPTX в Java backend

Студия находится на `/studio/`. Все API ниже находятся под `/api/generation`, требуют сессию пользователя (или локальный `AUTH_BYPASS`) и CSRF-токен для изменяющих запросов. Токен выдаёт `/api/auth/csrf`.

| Метод и путь | Назначение |
| --- | --- |
| `GET /health/ready` | Доступность сервиса и настройка AI |
| `GET /v1/models` | Список разрешённых моделей и `default_model` |
| `GET /v1/templates` | Реально установленные PPTX-шаблоны |
| `GET /v1/templates/{templateId}/context` | Поля, лимиты текста и привязка полей к слайдам |
| `POST /v1/prompts/preview` | Подготовленный JSON для Responses API; не вызывает OpenAI и не создаёт задачу |
| `GET /v1/presentations` | История пользователя с пагинацией `limit`, `offset` |
| `POST /v1/presentations` | Создание проекта: `template_id`, `topic`, `mode` (`openai` или `manual`), необязательный `model` |
| `GET /v1/presentations/{id}` | Статус проекта и URL скачивания |
| `PUT /v1/presentations/{id}/content` | Поля и решения о включении всех слайдов для ручного проекта |
| `POST /v1/presentations/{id}/cancel` | Отмена проекта, ожидающего материалов или находящегося в очереди |
| `GET /v1/presentations/{id}/download` | Текущий PPTX пользователя |
| `POST /v1/presentations/{id}/chat` | Правка: `{"message":"Сократи введение"}` |
| `GET /v1/presentations/{id}/versions` | Сохранённая история версий и запросов |

`POST /v1/presentations` поддерживает заголовок `Idempotency-Key` (8–100 латинских букв, цифр, `_`, `-`). Повтор запроса с тем же ключом возвращает существующий проект; изменение темы, шаблона или режима с прежним ключом возвращает 409. Лимит пользователя: 10 новых проектов в сутки и 3 незавершённых одновременно. Чат допускает 30 успешных правок в сутки.

Студия получает список моделей с сервера: GPT-6.1 Sol, GPT-6 Luna и GPT-6 Astra. Если `OPENAI_MODEL` задаёт другую модель по умолчанию, сервер также добавляет её в список. `model` принимают создание проекта, просмотр запроса и чат; неизвестная модель возвращает 422 до вызова OpenAI. Выбор сохраняется с проектом и учитывается в `Idempotency-Key`. Очередь использует сохранённую модель, даже если выбор в интерфейсе уже изменился. Чат использует модель проекта, пока пользователь не выберет другую для правки; в истории версий сохраняется модель каждой AI-операции. Ручная сборка не вызывает модель.

## Ручная сборка

Ручной проект создаётся со статусом `awaiting_content`. Клиент читает контекст шаблона и отправляет объект:

```json
{
  "fields": { "TITLE": "Заголовок", "AUTHOR": "Имя", "...": "остальные поля контекста" },
  "slides": [
    { "slide": 1, "include": true, "reason": "Выбрано пользователем" },
    { "slide": 2, "include": false, "reason": "Выбрано пользователем" }
  ]
}
```

Нужно передать все поля и по одному решению для каждого слайда шаблона. Номера слайдов должны быть целыми, уникальными и входить в диапазон шаблона. Хотя бы один слайд должен быть включён. Поля исключённых слайдов можно оставить пустыми. Длинный текст обрезается по лимиту соответствующего поля; сохранённый план содержит значения, которые попали в PPTX.

После отправки проект проходит `queued` → `running` → `succeeded` или `failed`. Очередь хранится в PostgreSQL; её обрабатывает планировщик Spring. Задача, оставшаяся в `running` дольше пяти минут, помечается ошибкой `worker_interrupted`.

## Чат и версии

Чат доступен для готовой презентации, чей план сохранён в базе. Запрос синхронный: сервер передаёт текущий план и просьбу пользователя в OpenAI, проверяет ответ и создаёт новый PPTX. Соединение имеет таймаут 10 секунд, чтение ответа — 2 минуты. Для этой функции при развёртывании нужно учитывать таймаут HTTP-прокси.

Правки одной презентации сериализованы блокировкой PostgreSQL: параллельный запрос получает 409 `edit_in_progress` до вызова модели. Версия, содержимое и текущий файл обновляются одной транзакцией. Каждый результат получает отдельное имя файла; неудачная правка сохраняет предыдущую успешную версию.

Файлы сохраняются на постоянном диске в `GODECK_DATA_DIR` (по умолчанию `backend/data/presentations/` при запуске через скрипт). Для нескольких экземпляров API нужен общий каталог с файлами. Миграции Flyway создают таблицы проектов и версий и применяются при запуске backend.

## Конфигурация

- `AUTH_BYPASS=false` — обычная авторизация. `pnpm backend:dev` включает bypass по умолчанию, только при loopback-адресе Java-сервера.
- `OPENAI_API_KEY` и `GODECK_OPENAI_ENABLED=true` — вызовы OpenAI; по умолчанию выключены.
- `OPENAI_MODEL` — модель Responses API, по умолчанию `gpt-6.1-sol`.
- `GODECK_DATA_DIR` — каталог выходных PPTX.

Ключ API остаётся в окружении backend и не включается в предварительный просмотр запроса. Публичный статический фронтенд требует отдельного развёртывания Java API и проксирования `/api/*`, как описано в основном README.
