# Материалы для генерации презентации

## Пользовательский путь

На `/studio` в режиме «Сгенерировать с AI» прикрепите документ, проверьте и при необходимости исправьте извлечённый текст. Укажите задачу, необязательные цель и аудиторию, выберите шаблон и создайте презентацию.

Извлечение текста не вызывает AI. Только при создании презентации окончательные материалы отправляются провайдеру. Генерация по одному описанию и ручная сборка из ответа LLM продолжают работать без документа.

## Поддержка и ограничения

| Параметр | Ограничение |
| --- | --- |
| Файл | Один PDF, DOCX или TXT до 5 МиБ |
| PDF | До 20 страниц, только текстовый слой |
| DOCX | Основной текст и простые таблицы в порядке документа |
| TXT | UTF-8, допускается BOM |
| Материалы | До 30 000 символов после нормализации |
| Инструкция | Обязательна, до 12 000 символов |
| Цель / аудитория | Необязательны, до 500 символов каждая |

OCR, чтение изображений и графиков, вложений, восстановление вёрстки и импорт оформления не входят в функцию. PDF со страницами без извлечённого текста требует подтверждения предупреждения; PDF совсем без текста отклоняется. Пустые, повреждённые, зашифрованные документы и неподдерживаемые кодировки отклоняются. Превышение лимита не приводит к молчаливому обрезанию.

## API и хранение

1. `POST /api/generation/v1/materials/extract`, multipart-поле `file`: возвращает `format`, `name`, `text`, `characters`, `pages`, `warnings`. Требуются сессия и CSRF; ответ не кешируется.
2. `POST /api/generation/v1/presentations`: существующий JSON дополнен необязательными `goal`, `audience`, `source: {format, name, text}`. Передаётся окончательный текст предпросмотра. Режим `manual` материалы не принимает.
3. `POST /api/generation/v1/prompts/preview` принимает тот же дополнительный контекст, но ничего не отправляет провайдеру.

Сервер повторно проверяет и нормализует материалы. Перед постановкой в очередь снимок атомарно сохраняется в `generated_presentations.generation_input_json`; worker не зависит от вкладки браузера. Старые задачи имеют `null` и сохраняют прежнее поведение. При повторе неизменённого создания используется один `Idempotency-Key`; хеш учитывает окончательные материалы и контекст.

Оригинал существует только во временном каталоге обработки. Парсер запускается отдельным локальным JVM-процессом с лимитами памяти, параллелизма и времени. Дополнительный сервис или deployment не нужны; текущий JRE/JDK должен содержать Java executable, а серверу необходим доступный временный каталог.

Снимки контекста очищаются по истечении 30 дней после завершения задачи; очередь и работающие задачи не очищаются. Плановая очистка периодическая, не точно в секунду истечения срока. Она не удаляет факты из готовых слайдов, опубликованных версий или PPTX.

При первоначальной генерации с дополнительным контекстом AI-аудит хранит безопасные метаданные вместо полного запроса и ответа. Это не меняет историю старых вызовов и не удаляет уже созданное содержимое презентации.

## Проверки

- `pnpm test:frontend`: API-клиент, состояние материалов, валидация, предупреждения, ключ повтора.
- `pnpm backend:test:unit`: парсеры, ограничения, нормализация.
- `pnpm backend:test:integration`: API, снимок очереди, идемпотентность, изоляция, диагностика, очистка.
- `pnpm test:e2e`: три формата до PPTX, ошибки, неполный PDF, потерянный ответ, запоздалая загрузка и существующие сценарии редактора.

E2E runner использует отдельную схему PostgreSQL и временный каталог. Только AI заменяется loopback HTTP-фикстурой с заведомо нерабочим ключом; UI, извлечение, очередь, БД и PPTX настоящие. Тесты проверяют интеграцию, но не качество ответа живой модели.

`GODECK_OPENAI_RESPONSES_URL` — серверная настройка с обычным адресом OpenAI по умолчанию. E2E runner задаёт собственный loopback URL; тестовую настройку не нужно переносить в production.
