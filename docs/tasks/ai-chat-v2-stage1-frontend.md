## 1. Цель

Чат над выбранным блоком отвечает полезно, а не отказом, показывает кнопки с готовыми просьбами, не теряет ленту при перезагрузке и
честно показывает, что стало с предложением после Ctrl+Z.

Frontend должен:

1. Показать ответ `alternative` с причиной и кнопками-просьбами.
2. Разрешить запрос над пустым полем и набор просьбы без выделения.
3. Загрузить ленту с сервера, листать старые записи, очищать.
4. Отправлять исход предложения, включая Ctrl+Z и Ctrl+Y.
5. Показать предупреждение «проверьте факты».

**Карточка «Применить» до этапа 2 остаётся.** Предложение не применяется автоматически: «Применить», «Другой вариант», «Отмена», выбор варианта и «Вернуть исходный» работают как сейчас. Автоприменение решено владельцем, но это этап 2.

## 3. API-контракт

Контракт дополняет `docs/ai-chat-editing.md`, раздел 7. Всё, что здесь не названо, остаётся прежним: аутентификация, CSRF, `snake_case`, формат ошибок, `Cache-Control: no-store`, длина в UTF-16 code units.

### Изменения `POST /api/generation/v1/presentations/{id}/editor/ai/text-edits`

| Поле | Изменение |
| --- | --- |
| запрос `text` | Может быть пустой строкой или только пробелами **только** у `action = custom`. Для `shorten` и `rephrase` прежняя ошибка 422 `invalid_text` |
| ответ `status` | Новое значение `alternative`. Сервер больше не отдаёт `unsupported` для новых запросов. Клиент обязан показывать `unsupported` из старых записей и повторов |
| ответ `reason` | Новое поле, строка или `null`. Заполнено только при `alternative` |
| ответ `suggestions` | Новое поле, массив строк, всегда присутствует. Не больше 3 строк, каждая не длиннее 80 символов. Каждая строка — готовая просьба `custom` для той же цели. Пусто при `ok` и `unchanged` |
| ответ `variants[].warnings` | Новое значение `check_facts`: в варианте есть общеизвестные факты без источника, пользователю нужно проверить |

Значения `reason`:

| `reason` | Когда | Что значит для пользователя |
| --- | --- | --- |
| `needs_source` | Нужны цитата, слова реального человека, статистика, цена или свежие данные | Без источника вставить нельзя |
| `style_panel` | Просьба о шрифте, размере, цвете, начертании | Это меняется на панели над слайдом |
| `out_of_scope` | Слайд целиком, несколько блоков, структура, фон, макет, изображения | Сейчас чат правит один блок |
| `advice` | Вопрос или просьба совета; `message` содержит ответ | Правки нет, есть совет |
| `clarify` | Просьба неоднозначна; `message` содержит один вопрос | Нужно уточнение |

Клиент обязан показывать неизвестное значение `reason` как обычную реплику с `message` и `suggestions`.

Пример ответа `200`:

```json
{
  "edit_id": "9c1d7b52-0f7e-4c55-8f3e-2d4b1a6e7c90",
  "request_id": "3f6c2a8e-1b7d-4c1e-9a52-6f0d2b7c9e11",
  "refines_edit_id": null,
  "status": "alternative",
  "reason": "needs_source",
  "message": "Подлинную цитату без источника вставить не могу: её нельзя придумывать.",
  "suggestions": ["Вставь заглушку [Цитата: имя, источник]", "Перескажи мысль своими словами без цитаты"],
  "action": "custom",
  "target": { "kind": "template_field", "slide_id": "slide-3", "field_key": "STATEMENT", "block_id": null },
  "source_text": "Оппозитный двигатель остаётся основой марки",
  "max_chars": 46,
  "hard_max_chars": 146,
  "variants": [],
  "model": "gpt-5.4-mini",
  "usage": { "input_tokens": 640, "cached_input_tokens": 0, "output_tokens": 90, "reasoning_tokens": 40 },
  "quota": { "limit": 100, "remaining": 86, "resets_at": "2026-11-01T09:12:00Z" },
  "replayed": false

```

Ответ `alternative` расходует единицу квоты как обычный вызов модели. Повтор с тем же `request_id` возвращает сохранённый ответ.

### `GET /api/generation/v1/presentations/{id}/editor/ai/history`

Лента одной презентации, новые записи первыми.

| Параметр | Правило |
| --- | --- |
| `limit` | 1…100, по умолчанию 50 |
| `before` | `next_before` прошлого ответа, необязательный |

Ответ `200`:

```json
{
  "items": [
    {
      "edit_id": "9c1d7b52-0f7e-4c55-8f3e-2d4b1a6e7c90",
      "created_at": "2026-10-31T09:12:00Z",
      "refines_edit_id": null,
      "action": "custom",
      "instruction": "сделай формальнее",
      "target": { "kind": "template_field", "slide_id": "slide-3", "field_key": "STATEMENT", "block_id": null },
      "status": "ok",
      "reason": null,
      "message": null,
      "suggestions": [],
      "source_text": "Мы делаем презентации быстро",
      "max_chars": 46,
      "hard_max_chars": 146,
      "variants": [ { "text": "Мы оперативно готовим презентации", "length": 33, "over_by": 0, "warnings": [] } ],
      "outcome": "applied",
      "outcome_variant": 0,
      "tracked": true
    }
  ],
  "next_before": null
}
```

| Поле | Значение |
| --- | --- |
| `status` | `ok`, `unchanged`, `alternative`, `unsupported`, `failed`. Запись `running` не отдаётся |
| `instruction` | Текст просьбы `custom`, иначе `null` |
| `source_text`, `max_chars`, `hard_max_chars` | `null` у `failed`: источник таких запросов не хранится. `variants: []`, `suggestions: []` |
| `outcome` | `applied`, `rejected`, `reverted` или `null` |
| `outcome_variant` | Индекс в `variants` при `applied`, иначе `null` |
| `tracked` | `false` у записей до этой версии: исход для них не собирался, и `null` не значит «не применено» |
| `next_before` | Непрозрачная строка или `null`, если записей больше нет |

Записи после очистки не отдаются. Ошибки: 404 `presentation_not_found`, 422 `invalid_input` при неверном `limit` или `before`.

### `POST /api/generation/v1/presentations/{id}/editor/ai/edits/{editId}/outcome`

Запись того, что пользователь сделал с предложением. Квоту не тратит, модель не вызывает.

```json
{ "outcome": "applied", "variant": 0 }
```

| Поле | Правила |
| --- | --- |
| `outcome` | `applied`, `rejected`, `reverted` |
| `variant` | Обязателен при `applied`, индекс существующего варианта; иначе `null` |

Ответ `204`. Запрос идемпотентен, последнее значение заменяет предыдущее. Переходы не ограничены: Ctrl+Y после Ctrl+Z снова даёт `applied`.

Ошибки: 404 `presentation_not_found`, 404 `ai_edit_not_found` (записи нет, она чужая, относится к другой презентации или очищена), 422 `invalid_input`.

Сбой этого запроса не влияет на редактор: клиент не показывает ошибку и не повторяет запрос больше одного раза.

### `DELETE /api/generation/v1/presentations/{id}/editor/ai/history`

Очищает ленту презентации. Ответ `204`, повтор безопасен.

- Тексты записей удаляются сразу; числовая телеметрия и учёт квоты остаются до штатного удаления через срок хранения.
- Записи `TEXT_EDIT` этой презентации удаляются из `presentation_ai_calls`. Генерация и студийный чат не затрагиваются.
- Выполняющийся запрос завершается как обычно и появляется в ленте.
- Повтор старого `request_id` после очистки даёт 502 `ai_edit_failed`.

Ошибки: 404 `presentation_not_found`.

## 4. Шаги

### Шаг 1. Типы, клиент, порт

- `generation-types.ts`: `status` с `alternative`; `reason: string | null`; `suggestions: string[]`; `check_facts` в предупреждениях; типы ленты и исхода. `reason` — строка, а не закрытый union: контракт требует показывать неизвестные значения.
- `generation-client.ts`: `aiHistory(id, {limit, before}, signal)`, `aiOutcome(id, editId, body)`, `clearAiHistory(id)`, обычные таймауты.
- `AiEditPort`: те же методы, HTTP и мок. Мок реализует контракт: лента в памяти, `__LONG__` и другие маркеры прежние.
- `scenarioFor` (`ai-edit-port.ts:103-108`): вместо `unsupported` сценарии `alternative`. Значение `unsupported` оставить в типах для старых записей.

### Шаг 2. Ответ `alternative`

`ReplyMessage` получает `target`, `reason`, `suggestions`. В `chat-reducer.ts:141-145` ветка не `ok` собирает такую реплику. Текст берётся из `message`; запасной текст по `reason`.

| `reason` | Показ |
| --- | --- |
| `needs_source` | Реплика и кнопки-просьбы |
| `style_panel` | Реплика, кнопки и подсказка: «Шрифт, размер и цвет меняются на панели над слайдом» |
| `out_of_scope` | Реплика и кнопки |
| `advice` | Ответ как обычная реплика, кнопки |
| `clarify` | Вопрос, кнопки, фокус в поле ввода |
| неизвестный, `unsupported` | Реплика, кнопки если есть |

Кнопка отправляет `custom` с текстом кнопки для `target` реплики, тем же способом, что `sendAction` (`use-ai-chat.ts:102-107`). Подпись — текст кнопки. Блокируется, пока для цели идёт запрос. Строка выводится как текст, без HTML и markdown.

Заменить тексты, обещающие только отказ: запасной текст `chat-reducer.ts:143`, пустая лента `ai-chat-panel.tsx:95-96`.

### Шаг 3. Пустое поле и ввод без выделения

- `disabledReason`: параметр `allowEmpty`. Для поля ввода пустой блок не причина блокировки; для быстрых кнопок причина: они не имеют смысла без текста. Подсказка: «Опишите, что написать в этом блоке».
- `sourceFor` и `runTextEdit` (`ai-chat-runner.ts:38`) не должны останавливать `custom` с пустым текстом. Быстрые действия с пустым текстом как раньше.
- Без выбранного блока поле ввода **активно**. Кнопка отправки активна. Отправка не идёт на сервер: в ленту добавляется локальная реплика «Выберите на слайде блок, к которому относится просьба. Текст просьбы сохранён», `draft` не очищается. Квота не тратится. После выбора блока просьбу можно отправить одним нажатием.

Это временное поведение: на этапе 2 такой запрос станет ходом. Вынести условие в одну функцию, чтобы этап 2 менял одну строку.

### Шаг 4. Предупреждение `check_facts`

В `warningTexts` (`ai-proposal-card.tsx:13-26`): «Проверьте факты: в тексте есть сведения без источника». Предупреждение не блокирует «Применить». Сервер уже убрал цитаты, статистику и цены.

### Шаг 5. Лента с сервера

- При первом открытии чата (`active`, как каталог, `use-ai-chat.ts:65-77`) загрузить первую страницу. Ошибка загрузки не мешает работе: реплика «Не удалось загрузить историю» и «Повторить».
- Новое действие `historyLoaded`: записи добавляются **перед** сообщениями сессии, без дублей по `edit_id`. Чистая функция `messagesFromHistory(items, catalog, deck)` в отдельном файле `ai/chat-history.ts`, с тестами.
- Запись даёт сообщение пользователя (`instruction` или подпись действия из каталога) и ответ.
- Чип считается по текущему документу. Блока нет: «Удалённый блок», кнопки применения скрыты.

| Запись | Показ |
| --- | --- |
| `ok`, `applied` | Карточка «Применено», «Вернуть исходный» |
| `ok`, `rejected` | «Отклонено» |
| `ok`, `reverted` | «Исходный текст возвращён» |
| `ok`, есть запись с `refines_edit_id` на неё | «Заменено уточнением» |
| `ok`, `null`, `tracked: true` | Новый статус `stale`: «Не применено», кнопка «Применить» |
| `ok`, `null`, `tracked: false` | «Статус неизвестен», кнопок нет |
| `alternative`, `unsupported`, `unchanged` | Реплика, кнопки если есть |
| `failed` | «Не удалось получить ответ», без «Повторить» |

- `stale` не попадает в `pending`: следующая просьба идёт от текста блока (`sourceFor`, `chat-reducer.ts:208-213`).
- «Применить» у `stale` идёт через `replaceText` (`use-ai-chat.ts:129-140`): изменившийся текст требует подтверждения.
- `baseText` записи: `source_text` корневой записи цепочки `refines_edit_id`; если корень удалён, свой `source_text`.
- Кнопка «Показать раньше» при непустом `next_before`. Прокрутка не должна прыгать.
- Подпись в пустой ленте и рядом с кнопкой очистки: «История хранится 90 дней».

### Шаг 6. Очистка

Кнопка в заголовке панели, подтверждение «Очистить историю чата? Презентация не изменится». После успеха `reset` сообщений, кроме запросов в работе. Ошибка — реплика в ленте. Документ, Ctrl+Z и квота не меняются.

### Шаг 7. Исход и Ctrl+Z

- `applied`, `reverted`, `rejected`, «Вернуть исходный»: отправлять `outcome` из `use-ai-chat.ts:142-157`. Не ждать ответа, не блокировать интерфейс, не показывать ошибку, не больше одного повтора.
- Новый статус `undone`: «Отменено». Чистая функция `reconcileApplied(messages, deck)`: у применённого предложения текст блока равен `baseText` → `undone`, отправить `reverted`; у `undone` текст снова равен `appliedText` → `applied`, отправить `applied`.
- Вызывать при изменении `deck`. `deck` передать в хук из `editor-shell.tsx:95-101`.
- Проверять только последнее предложение цели. Текст, изменённый вручную на третий вариант, статус не меняет. Ручной ввод ровно того же текста считается отменой: это допустимо.
- `FOOTER`: сверка идёт по цели предложения.
- Запрос исхода для записи без `edit_id` не отправлять.

Ctrl+Z из поля чата на этом этапе не трогать: это правка этапа 2.

## 5. Что НЕ делать

- Не применять предложения автоматически, не убирать карточку и `pending`.
- Не добавлять панель «Назад», «До / После», отметки в ленте слайдов, сворачивание листа чата.
- Не менять обработку Ctrl+Z в `editor-shell.tsx`.
- Не добавлять ход, правку слайда, разбор номера слайда, поиск, источники, настройки лимитов, показ провайдера.
- Не добавлять чату смену шрифта, размера, цвета, начертания.
- Не писать ленту в `localStorage` и `sessionStorage`.
- Не отправлять историю в запросе к модели.
- Не трогать `text-format-toolbar.tsx`, `use-editor-state.ts`, autosave, генерацию, студийный чат.
- Не менять логику повторов `ai-chat-runner.ts` и `errorReply`.
- Не коммитить без запроса.

**Задел для этапа 2, обязателен.** `messagesFromHistory`, `reconcileApplied`, реплика с `suggestions` и отправка исхода не должны зависеть от кнопки «Применить»: этап 2 применит правку сразу и переиспользует их. Новые статусы — в общем `ProposalStatus`.

## 7. Критерии приёмки

1. **Анекдот.** Выделен блок, «перескажи в виде анекдота»: карточка «было / стало» с «Применить».
2. **Цитата.** «Добавь цитату главного инженера Subaru»: реплика с причиной и кнопками, выдумки нет; кнопка «Вставь заглушку…» создаёт карточку.
3. **Стиль.** «Поставь другой шрифт»: реплика направляет на панель над слайдом, ничего не обещает.
4. **Совет.** «Что здесь можно улучшить?»: ответ и кнопки.
5. **Пустое поле.** «Заполни этот блок»: карточка; «Сократить» недоступно.
6. **Без выделения.** Просьба не теряется, нет запроса к серверу, после выбора блока отправляется.
7. **Перезагрузка.** Лента, статусы и старые реплики на месте. Неприменённое предложение показано как «Не применено», его можно применить со сверкой текста.
8. **Ctrl+Z.** Применённая карточка показывает «Отменено», Ctrl+Y — «Применено», исход дошёл до сервера.
9. **Сбой.** Ошибка истории или исхода не мешает правке.
10. **Очистка.** Лента пуста, презентация и Ctrl+Z не изменились.
11. **Карточка.** «Применить», «Другой вариант», «Отмена», «Вернуть исходный» и уточнения работают как раньше, правка не применяется сама.
12. **Проверки.** `pnpm test:frontend`, `pnpm typecheck`, `pnpm verify` зелёные.

## 8. Порядок работы

2. Шаг 1: можно работать на моке, не дожидаясь backend.
3. Шаги 2–4.
4. Шаги 5–6.
5. Шаг 7.
